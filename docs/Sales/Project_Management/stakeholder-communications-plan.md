# Stakeholder And Communications Plan

## Stakeholders

| Stakeholder | Need | Message |
| --- | --- | --- |
| Startup founders | Fast business insight and reporting. | Upload one dataset, ask a question, and download a report. |
| SME owners | Clear view of sales, costs, margins, and readiness. | Use datasets, Business Profile, and Accountancy to improve decisions. |
| Consultants and agencies | Client-ready analysis from exported data. | Use UseClevr to prepare summaries and follow-up questions. |
| Accountancy-adjacent users | Pre-accounting and tax-context readiness. | Organize data before professional review. |
| Super-admin operators | Customer, support, billing, and trace visibility. | Use platform tools to manage operations. |
| Developers and AI agents | Stable implementation and documentation flow. | Keep requirements, changelog, TODOs, docs, and validation aligned. |
| Sales and marketing | Current product story and roadmap boundaries. | Use Sales docs as the current product source for commercial messaging. |

## Communication Channels

| Channel | Audience | Use |
| --- | --- | --- |
| Website | Public visitors | Product offer, pricing, FAQ, signup, contact. |
| Dashboard | Signed-in users | Onboarding, upload, AI, reports, support, billing. |
| Help chat | Public and signed-in users | FAQ discovery and support handoff. |
| Tickets | Signed-in users and super-admins | Support requests and resolution. |
| Sales docs | Sales and marketing | Project description, business case, demo and campaign planning. |
| Developer docs | Developers and AI agents | Implementation and deployment guidance. |
| TODO queues | Project operators and AI agents | Active, future, done, and ignored work. |

## Communication Cadence

- Review Sales docs before demos and public campaign updates.
- Review requirements and changelog before release notes.
- Review risk and issue registers before major deploys.
- Review help chat misses and tickets after demo sessions.
- Review lessons log after major AI-agent work cycles.

## Message Controls

- Use current product state for all sales statements.
- Label roadmap items clearly.
- Avoid regulated-advice claims.
- Avoid internal implementation details in customer-facing copy.
- Use demo screenshots and data that match the current UI.
